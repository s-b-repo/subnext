# Architecture Audit — August 2026

Response to [issue #1](https://github.com/s-b-repo/subnext/issues/1), which asked
for two things: a secure `.context` architecture, and a repository-wide audit
that resolves what it finds rather than only listing it.

This is the record of what was found, what was fixed, and what is still open.
`AUDIT.md` is a different document — a bad-pattern scan of the Rust — and stays
what it is.

---

## 1. Flaw inventory, by severity

### Critical — a claim the system could not keep

| # | Flaw | Resolution |
|---|---|---|
| C1 | **No integrity layer at all.** The store was one plaintext JSON file. An edited store reloaded silently; bit rot was undetectable; there was no way to tell a corrected memory from a corrupted one. | The `.context` container: content-addressed objects, Merkle root, chained generations, anti-rollback. [context integrity](architecture/context-integrity.md) |
| C2 | **Nothing separated integrity from trust.** Provenance was enforced, but a well-formed object from any source was equally admissible. | `TrustLabel` + `AdmissionPolicy`, checked *after* integrity, so a valid signature explicitly does not confer trust. |
| C3 | **The chain covered only part of a checkpoint.** *(introduced during this work, caught by `bench --tamper`.)* Timestamp, object count and policy hash were editable without breaking the chain. | The chain digest now covers the whole checkpoint body. |
| C3b | **The chain reconstructed `schema` from a constant**, so the value on disk never entered the digest. Found by the exhaustive field walk, not by the one-off regression test for C3. | The parsed value is carried into the digest, *and* an unknown schema is refused. |
| C4 | **Objects were re-addressed on every commit.** *(introduced during this work.)* The generation was inside the hashed body, so unchanged material got a new address each write and the store grew by its full size per commit. | Generation moved to the sidecar; the address depends on content alone. Regression test: `reads_and_unchanged_saves_do_not_mint_generations`. |

### High — a stated deliverable that did not exist

| # | Flaw | Resolution |
|---|---|---|
| H1 | **No failure-mode catalogue**, though the roadmap listed one as a Phase 3 deliverable. | [failure modes](architecture/failure-modes.md) — 20 modes with detection, containment and recovery. |
| H2 | **Workspace rebuild cost was unmeasured**, making "destroy and rebuild at any time" a nominal guarantee. | [workspace rebuild](architecture/workspace-rebuild.md) + `bench --rebuild`. Mean cold rebuild 1.55 ms. |
| H3 | **Baselines were both truncations.** Full context and a sliding window fail the same way, so beating them proved little. | `bench --baselines` adds RAG, summarize-all and recursive map-reduce — and then a second corpus where DCR scores 2/5 and loses. |
| H6 | **`provenance.md` overclaimed on conflict handling**, implying contradictions always keep both sides. Two plain disagreeing claims are settled by ingest order with no marker. | The rule is stated as a table; the consequence is priced as a benchmark row. |
| H4 | **Evidence had no epistemic dimension.** A model-inferred claim and a read fact were indistinguishable in the window. | `Origin` (observed / externally sourced / computed / inferred / hypothetical), rendered whenever it is not `Observed`. |
| H5 | **No architectural alternatives were ever written down**, so the design read as the only option considered. | [alternatives](alternatives.md) |

### Medium — internal inconsistency

| # | Flaw | Resolution |
|---|---|---|
| M1 | **`RESULTS.md` documented the Python build** after the Rust port: `python -m dcr`, `index.py`, a stale test count. | Regenerated from the Rust build. |
| M2 | **Open questions #5 and #9 were listed as unresolved** although both were implemented (bounded cascades, snapshot isolation). | Moved to a *Resolved* section pointing at the code. |
| M3 | **A contradicted node reported `Status::Fresh`.** The dispute existed only on the edges, so the state could not report its own contested condition. | `Status::Contradicted`, set on contradiction and settled on supersession. |
| M4 | **Prefetch metrics were listed in the evaluation design** but lived only inside `Speculator::stats()`. | `prefetch_hit_rate` and `wasted_builds` are in the telemetry report. |
| M5 | **An open question had no distinct state.** `Kind::OpenQuestion` nodes were `Fresh`, indistinguishable from settled facts. | `Status::Unresolved` is their initial state. |

### Low — noted, not fixed

| # | Flaw | Why not |
|---|---|---|
| L1 | Retrieval is `O(nodes)`; the cost model needs sub-linear retrieval. | Already documented as the known gap. It is an ANN index swap behind three methods, not a redesign — and it is the next real piece of work. |
| L2 | The benchmark corpus is synthetic. | True and unfixed. A real long-horizon agent trace would be better evidence; none is available. |
| L3 | `dcr/` (Python) has drifted from `src/` (Rust). | **Closed by removal.** It had fallen seven features behind and still served superseded values on a shape the Rust was fixed for. Kept in git history; see `IMPLEMENTATION.md`. |

## 2. Contradictions resolved

**"Zero dependencies" vs. "cryptographically authenticated."** These are in
genuine tension: real signatures and AEAD cannot be responsibly hand-rolled. The
resolution is not to pick one — SHA-256 is implemented in-tree because a hash
can be verified against published NIST vectors, and signatures and encryption
are traits with **no bundled implementation**. The store then records honestly
that it is unsigned rather than implying protection it does not have. The
zero-dependency claim survives with that qualification stated wherever it appears.

**"Nothing is ever deleted" vs. quarantine.** Quarantine moves an object out of
the store, which looks like deletion. Resolved by making the loss explicit: the
object goes to `quarantine/` with a reason record, and the scrubber seals a new
generation recording that the object set changed. Nothing is deleted silently.

**"Contradictions are kept, both sides" vs. supersession clearing the marker.**
A correction produces both a `contradicts` and a `supersedes` edge. If
contradiction were permanent, every correction would leave a permanent open
dispute. Resolved by `settle()`: a node returns to `Fresh` when nothing *live*
disagrees with it, while the edge and the superseded node remain for the audit.

## 3. Revised invariants

Added:

> **I-7.** No context enters trusted reasoning unless integrity is verified, the
> signature and provenance are valid, the generation is acceptable, the schema
> is valid, and policy allows it.

> **I-8.** Every trusted context state is reproducible from its chained history.

> **I-9.** An object's address is a function of its content alone. Usage,
> location and replica count are metadata and are never hashed.

> **I-10.** A repair may only use a source that verifies independently.

> **I-11.** Derived material is labelled with its origin wherever it is
> rendered. An inference never reaches the reasoner looking like an observation.

Unchanged and still enforced: provenance at `upsert`, nothing deleted, stale
nodes never admitted, demotion before eviction, budget never silently exceeded.

| Interface | Change |
|---|---|

## 5. Benchmark and falsification plan

Two tables. The first (`bench --baselines`, standard corpus, 300 turns, 27,362
tokens of history, `B_attention` = 1200):

| probe | full | RAG | summarize | recurse | DCR |
|---|:---:|:---:|:---:|:---:|:---:|
| corrected fact (mid-history) | ok | ok | MISS | ok | ok |
| corrected fact (late) | ok | ok | MISS | MISS | ok |
| old fact, never repeated | MISS | MISS | MISS | MISS | ok |
| exact quote | MISS | MISS | MISS | MISS | ok |
| justification / multi-hop | ok | ok | MISS | ok | ok |
| detail buried in a long span | ok | ok | MISS | ok | ok |
| corrected fact (very late) | ok | ok | ok | ok | ok |
| **correct** | 5/7 | 5/7 | 1/7 | 4/7 | **7/7** |
| **mean tokens/query** | 27,362 | 1,168 | 1,197 | 31,074 | **462** |

Read it honestly:

- **RAG ties full context at 5/7.** Plain top-k retrieval is a strong baseline
  and it answers most probes at 2.5× DCR's token cost. The gap is not "DCR
  retrieves better" in general — it is two specific probes: a fact that was never
  repeated (similarity has nothing to latch onto) and an exact quote (top-k
  returns the right chunk, not the right bytes).
- **Summarize-all collapses to 1/7.** Uniform compression at the same budget
  destroys precisely the details the probes ask for. This is the strongest
  evidence that *selective* representation beats uniform compression.
- **Recursive costs more than full context** (31k vs 27k tokens) because it
  reads every chunk and then reads its own digest. Unlimited coverage is not
  free, and charging for it is the honest accounting.
- **The reasoner is a line-matcher for every column**, so this compares context
  assemblies, not models. Full-context accuracy is a floor, not a ceiling.

### The table that actually proves DCR loses

The standard corpus does not discriminate — RAG ties full context, because most
of those probes are findable by similarity. A second corpus is built so that
similarity is misleading and refusing is sometimes correct:

| probe | full | RAG | summarize | recurse | DCR |
|---|:---:|:---:|:---:|:---:|:---:|
| lexical decoy on a stale fact | ok | ok | MISS | ok | ok |
| three-hop dependency (context) | ok | ok | MISS | ok | ok |
| stale derivation (must refuse) | MISS | MISS | ok | ok | **MISS** |
| absent fact (must refuse) | MISS | MISS | ok | MISS | **MISS** |
| contested fact (order decides) | MISS | MISS | MISS | MISS | **MISS** |
| **correct** | 2/5 | 2/5 | 2/5 | **3/5** | 2/5 |
| **mean tokens/query** | 27,382 | 1,133 | 1,180 | 31,180 | **237** |

**DCR loses this table**, and the three failures are the most valuable output of
the audit: a derived figure stated as prose is never invalidated; a dense window
makes near-miss answers easy to reach for; and two disagreeing sources are
settled by arrival time. All three are now tracked in `TODO.md` §10.

Designing this corpus produced a methodological finding worth repeating: three
of the five probes had to be rewritten because their vocabulary collided with
the noise generator, so they measured the collision rather than the property.
A probe that fails for an uninteresting reason looks exactly like a probe that
fails for an interesting one.

Security claims are falsified separately by `bench --tamper`, which corrupts an
object, rewrites a historical checkpoint and attempts a rollback, then asserts
each is caught. It found C3 above.

Still missing, and worth stating: no latency comparison against a real model, no
non-synthetic corpus, and no evaluation under a reasoner that can paraphrase.

## 6. What remains a hypothesis

Claims in this repository that are argued, not demonstrated:

1. **`O(k + r)` holds at real scale.** Measured to 3,000 turns with flat `k`;
   retrieval is still linear, so the composite claim is unproven beyond that.
2. **Solution B can be a much smaller model.** Asserted throughout. Node
   extraction and contradiction detection are the parts that plausibly still
   need strong reasoning, and nothing here establishes where the quality cliff is.
3. **Speculation pays for itself.** The machinery, the metrics and the budget
   isolation exist; the benchmark's prefetch hit rate is `n/a` because the
   probes do not exercise it. Unproven either way.
4. **The ladder's four levels are the right four.** L3 carries nothing in the
   ablation. It may be one level too many.
5. **Extraction quality is tolerable.** The scanner is conservative by design;
   what error rate a model-driven extractor would introduce is
   [open question #2](open-questions.md) and is not measured.
6. **Tamper-evidence is sufficient for the threat model.** It is sufficient
   against corruption and casual editing. Against an attacker with write access
   it is not, and no bundled component changes that.

## 7. Changes made, and why

| Change | Class |
|---|---|
| SHA-256, Merkle tree, canonical encoding | correctness fix — content addressing needs a real hash |
| `.context` container, chained checkpoints, anti-rollback | security fix |
| `ContextGateway`, trust labels, key roles | security fix |
| Scrubber, replicas, quarantine | correctness fix — detection without repair is half a mechanism |
| Chain covers the whole checkpoint body | security fix (found by `bench --tamper`) |
| Generation out of the hashed body | correctness fix (found by CLI use) |
| Usage counters in their own object | efficiency — the store must grow with knowledge, not reads |
| `Origin`, `Status::Contradicted`, `Status::Unresolved` | architectural improvement |
| `bench --baselines` / `--rebuild` / `--tamper` | falsification |
| Prefetch metrics in the report | observability |
| Failure modes, rebuild cost, alternatives, this document | documentation of existing gaps |
| `RESULTS.md` regenerated | stale-claim fix |

Not done, deliberately: no cosmetic rewrites, no renaming for its own sake, and
no guarantee weakened to make the design easier to describe.

## 8. Second pass — flaws introduced by the first

The issue asked for an independent pass looking for damage done by the fixes.
Four things surfaced:

1. **C3** (partial chain coverage) — found by the tamper probe, fixed.
2. **C4** (per-commit re-addressing) — found by running the CLI rather than the
   tests, fixed. Worth noting: the test suite was green while the bug was
   present, because no test asserted that an unchanged save was free. It does now.
3. **A test asserting the old contradiction behaviour** now asserts the new one,
   and gained a companion test for the settle path. Changing a passing test is a
   risk, so the reason is recorded here as well as in the test.
4. **A benchmark that measured the wrong thing.** The first `--rebuild`
   implementation timed a plan *after* `rebuild_workspace`, which had already
   replanned — so "cold" and "warm" were both warm and the numbers were
   identical. Fixed; the real gap is 12×. The lesson is the same as C4: a number
   that looks plausible is not a number that was checked.
5. **Regression tests that pin one case instead of the class.** C3 and C4 each
   got a test for the exact failure that was noticed. Replacing them with
   exhaustive walks — every checkpoint field must break the chain, every object
   field must break the address — immediately found C3b, which the one-off test
   could not have. Where an invariant is "all of X", test all of X.
6. **Concurrent edits from two other sessions.** `src/planner.rs`,
   `src/indexer.rs` and `src/index.rs` were modified outside this work while it
   was in progress — superseded-source evidence excluded from seeding,
   transition-verb extraction, an LSH index, and the removal of the Python
   implementation. The headline moved four times mid-audit (467.3 → 457.1 →
   498.7 → 461.9), and a doc sweep completed against one of those values was
   stale before it was committed. Two lessons, both cheap: measure in a detached
   worktree at a fixed revision rather than in a working tree others are editing,
   and state the revision in the artefact so a reader can tell which measurement
   they are holding.

   A third lesson came from the sessions themselves rather than the numbers, and
   it accounts for both of the cross-session errors that actually occurred:
   **do not report state you have not re-checked at the moment of reporting.**
   Every wrong thing said between sessions today was true when it was observed
   and false when it was sent — a file described as uncommitted that had been
   committed, work attributed to the session that had not done it, a tree
   described as clean that had moved. Neither error came from measuring at the
   wrong revision; both came from reporting an observation with a stale
   timestamp. Re-check immediately before asserting, or say when you looked. It
   is cheap to state and hard to follow, because the failure feels like
   diligence: in each case the check *had* been done, just not at the moment of
   speaking.

   The numbers in this document are re-measured against the combined tree and
   pinned to `3821cc5`. Sub-linear retrieval (an LSH index behind `VectorIndex`)
   has since landed, and it moved them again — approximate retrieval changes
   which nodes seed, so the window changes with it. Three sessions edited this
   repository concurrently while the audit was being written, which is itself
   the finding recorded in §10.

7. **Checks that could not be exercised — four of them.** A metric that could
   not be exercised in the configuration that disabled it; a pass reachable
   through an unobserved shortcut; an assertion compiled out of the build that
   ran it; and the verification of that third fix, which fired correctly and
   kept no reproducible record, so the paper briefly claimed a check a reader
   had to take on trust. The fourth is this session's, committed while fixing
   the third — describing this class confers no immunity to it. Verifying a
   control means making it *fail* on purpose; confirming that it passes is
   exactly what every broken version already did.

   The number remaining is unknown, and the method matters more than the count.
   All four were found by someone asking a differently-shaped question about
   something already checked. **None came from re-running an existing check more
   carefully.** Three sessions and a public comment thread produced four;
   harder scrutiny of the same shape produced none of them. Only one has a
   mechanical form — no debug assertions in release-only paths, greppable,
   currently green, proposed to the session that owns the audit tool. The other
   three do not, so the honest expectation is that cross-review rather than
   tooling is what would find a fifth.

8. **An edit that silently did nothing.** Finding 7 was written once before
   this and never landed: the script used `str.replace` without asserting the
   pattern matched, so a stale pattern produced a successful-looking run and an
   unchanged file. It was noticed only because a later edit to the same region
   failed loudly. Every subsequent edit in this sweep asserts before writing.
   This is finding 7's own shape — a check that cannot fail — arriving in the
   tooling used to record finding 7.

## 9. What the paper does not cover

[`paper/dcr-bounded-attention.pdf`](../paper/dcr-bounded-attention.pdf)
(DCR-TR-2026-01) predates this work. Nothing in it is contradicted — the
context-rot numbers it reports are unchanged, and were re-run to confirm it —
but it is narrower than the repository now is: it has no integrity section, no
retrieval baselines, and no rebuild measurement. It is left at its published
revision rather than silently extended, since it is a dated report with a public
URL. The material that would extend it lives in
[context integrity](architecture/context-integrity.md),
[workspace rebuild](architecture/workspace-rebuild.md) and
[RESULTS.md](../RESULTS.md).

## 10. Still open

Everything in [open questions](open-questions.md) that is not marked resolved,
plus the three durability items deferred by choice: erasure coding,
hardware-backed keys, and external notarisation. Each is deferred with a stated
